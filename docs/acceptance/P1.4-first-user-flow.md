## Supabase Data API preflight (authenticated anon JWT)

Request:

```http
GET /rest/v1/hives?select=id&limit=1
Accept-Profile: hive3
apikey: <anon>
Authorization: Bearer <anon>
```

**Result:** HTTP **406**, `PGRST106` — `Invalid schema: hive3`. Exposed schemas reported: `public`, `graphql_public`, `hive` only.

**Impact:** `apps/web` uses `client.schema('hive3').from('hives')` with the user session JWT. Hive list/create/get **cannot persist** until **`hive3` is added to Supabase API → Exposed schemas** (dashboard change on the shared project). This is not fixable in application code without violating the hive3-only data boundary or applying DDL.

## Auth errors and account recovery (2026-10-21)

Registration, login, password reset, and signed-in password change stay on the existing Supabase client and `/auth/callback` allow-list. No Hive DDL, Edge Function, or provider-admin changes.

| Check | Result |
|-------|--------|

| `npm run test` in `apps/web` | Pass (33 tests) |
| Login, invalid email | “Enter a valid email address.” Email kept on the form |
| Login, unknown credentials | “That email or password is incorrect…” Structured log `auth.sign_in` / `invalid_credentials`; no email or password in the log |
| Register, short password | “Use a password between 10 and 72 characters.” Log diagnostic `password_policy` |

| `/reset-password` without a recovery session | Redirects to `/forgot-password?error=link_invalid` |

Not exercised in the browser: opening a live recovery email, setting a new password, or changing a password while signed in. Those actions require a real inbox and an existing session. Callback failures for expired and reused links are covered by the mapper tests and the `link_reused` / `link_invalid` screens.
