# P1.6 — Database-backed upload policy (acceptance)

## Prerequisites

1. P1.5 upload migrations applied (`20261021150000`, `20261021150100`).
2. Apply **P1.6** migration `supabase/migrations/20261021160000_hive3_m1_upload_product_policy.sql` in Supabase SQL Editor (operator authorization).
3. Redeploy Edge Function `v1-documents` from `supabase/functions/v1-documents/` (Dashboard → Edge Functions).
4. Web app deployed or running locally with Supabase env configured.

Optional qualification (read-only): `supabase/qualification/p1.6_upload_policy_assertions_readonly.sql`.

## Manual Supabase apply

1. Open Supabase project → SQL → New query.
2. Paste the full contents of `20261021160000_hive3_m1_upload_product_policy.sql`.
3. Run once; confirm one row in `hive3.upload_product_policy` with `is_active = true`.
4. Confirm `storage.buckets.file_size_limit` for `hive3-source-documents` is `26214400`.

## Edge deploy

1. Dashboard → Edge Functions → `v1-documents` (create if missing).
2. Deploy bundle from repo; ensure secrets: `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`.
3. Smoke: authenticated `op: "quota"` returns `{ quota, policy }` with `policy.commercial_offer.payments_enabled: false`.

## UI acceptance (one procedure)

1. Sign in; open a Hive you own → **Your documents**.
2. Confirm quota chip shows `N of 10 uploads left this month (UTC)` from API (not hardcoded env).
3. Confirm helper text: `PDF, PNG, JPG, or DOCX — up to 25 MB each.`
4. Upload a small PDF; confirm success and quota decrements.
5. In Supabase, temporarily set active policy `max_file_bytes` to `1048576` (1 MiB); **do not change app env**.
6. Refresh Hive documents page; helper text should show `1 MB` limit; a 2 MiB PDF should be rejected client-side.
7. Restore `max_file_bytes` to `26214400`.
8. Exhaust free quota (or simulate with test user); confirm offer reads **10 additional uploads — $5 one time** and footnote **Payments coming soon…**; **Choose files** stays disabled (no checkout).

## Negative checks

- Deactivate all policies (`is_active = false`): quota API fails safely; uploads unavailable (no silent grant).
- `text/plain` upload rejected at prepare/complete (SQL + UI).
- Concurrent completes at quota boundary: second registration raises `quota_exceeded` (P1.5 behavior preserved).

## Out of scope

- Stripe, paid credit ledger, admin UI for policy edits (operator SQL only).
