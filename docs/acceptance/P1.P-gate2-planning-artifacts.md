# P1.P Gate 2 — Planning artifact persistence acceptance

**Status:** **IMPLEMENTED (repo) — LIVE ACCEPTANCE DEFERRED** (2026-10-22)

Gate 2 adds **contracts + Worker persistence** for three immutable run-scoped artifacts on **`hive3.study_run_artifacts`** (Gate 1). It does **not** require P2.2-DP.I runtime planning, Canonical Study merge, or new SQL tables for the three `@1` JSON payloads.

## Prerequisites (live pass)

- Gate 1 migration(s) applied, including Worker RPC EXECUTE hardening when needed.
- Gate 1 readonly qualification: `supabase/qualification/p1p_gate1_processing_persistence_assertions_readonly.sql`.
- Worker deployed with **service_role** Supabase client (same as P1.5-processing).
- Optional: Gate 2 readonly qualification (when added): `supabase/qualification/p1p_gate2_planning_artifact_assertions_readonly.sql`.

## Artifact kinds (normative)

| `artifact_kind` | Contract | Typical `revision` |
|-----------------|----------|-------------------|
| `study-question-set@1` | Frozen merged questions; `intent_id` + `text_hash` only (no verbatim intent) | `1` per run |
| `study-plan@1` | References `study_question_set_hash`; investigation schedule / reuse summary | `1` per run |
| `study-question-coverage@1` | Per-question `evidence_coverage` + `answer_status` | `1` per run |

Design shapes: `docs/design/p2.2-dp.d/UNIFIED-QUESTION-PLANNING.md` §7–§8.

**Hash semantics (repo):**

- Row `content_sha256` = SHA-256 of `JSON.stringify` of the stored payload (Gate 1 / P1.5).
- Question set `content_hash` = SHA-256 of the same payload **without** the `content_hash` field (semantic digest).
- `study-plan@1` / `study-question-coverage@1` `study_question_set_hash` must equal the persisted question set `content_hash` (Worker-enforced before RPC).

## Minimum acceptance (controlled dev) — **release blockers until passed**

| # | Scenario | How to verify |
|---|----------|----------------|
| 1 | Persist question set | Service role: `hive3_p1p_worker_put_run_artifact` with kind `study-question-set@1`, valid payload, `contract_version` = kind; reload via `hive3_p1p_worker_get_run_artifact`; `content_sha256` matches canonical JSON hash |
| 2 | Persist study plan | Put `study-plan@1` with `study_question_set_hash` matching question set hash; get returns identical payload |
| 3 | Persist coverage | Put `study-question-coverage@1`; get returns identical payload; incomplete coverage fields allowed (partial run) |
| 4 | Idempotent retry | Repeat put #1 with same revision + hash → same artifact id; no duplicate rows |
| 5 | Hash conflict | Same `(study_run_id, artifact_kind, revision)` with **different** `content_sha256` → `artifact_revision_hash_conflict`; row unchanged |
| 6 | Interrupted write recovery | After successful question set put, simulate Worker retry: put plan + coverage; all three kinds readable; run row unchanged except unrelated stage transitions |
| 7 | Intent privacy | Question set payload contains **no** verbatim `request_text`; owner `hive3_p1p_get_intent` still returns full text; artifacts not SELECT-able by `authenticated` |
| 8 | Cross-Hive denial | Owner of Hive B cannot `hive3_p1p_get_study_run` for Hive A run; Worker put/get for run on Hive A succeeds only with service role (no cross-tenant read via owner RPCs) |

### Version / contract validation (Worker boundary — unit + optional live)

- Malformed JSON or wrong `contract_version` for kind → Worker rejects **before** RPC (`INVALID_REQUEST` / validation code per `error-envelope@1`).
- Read path: stored hash must match recomputed hash of `payload_jsonb` or treat as persistence corruption (`INVALID_REQUEST` / internal diagnostic).

## Negative cases (required)

- **Missing prerequisite artifact:** put `study-plan@1` when question set hash does not match any artifact on run → Worker validation failure (implementation-defined code; must not write inconsistent plan).
- **Oversized payload:** exceeds `study_run_artifacts_payload_size` (512 KiB) → SQL error mapped to persistence boundary; no partial row.
- **Cross-run artifact access:** get with valid kind but wrong `study_run_id` → `artifact_not_found` or `study_run_not_found`.
