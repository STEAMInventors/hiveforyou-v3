## Intent coverage (exact match supplement gate)

Exact pack structures call `supplement_schema` when **any material intent token** (length ≥ 4, not a stopword) is not covered by existing field keys/titles/descriptions. Contextual fillers (`child`, `term`, etc.) are excluded so boilerplate intents do not force a model call. This replaces the prior **two uncovered tokens** threshold, which could skip supplement when a single material requirement (for example `homeschool`) was uncovered.

Implementation: `apps/worker/src/plan/intent-coverage.ts` (`materialUncoveredIntentTokens`, `intentNeedsSupplementalFields`).

Field-key safety:

- Generated payloads: duplicate keys → `MODEL_OUTPUT_INVALID` / `duplicate_field_key`.
- Partial match merge: `mergeReusableFacts` keeps pack reusable fields; generated keys that collide are dropped (not overwritten).
- Exact supplement: `mergeSupplementalFields` appends only novel keys.
